## Verdict

The promise still holds in its narrow form, and the guard did not move: `MessageGuard.kt` is identical to the one audited at 15980e4. Of 28 claims, 15 are proven, 9 partial, 2 false and 2 unverifiable (25 claims re-traced, 2 added from the README: C26 and C27, and C28 added at the re-check of the Play Store source). The three over-claims found on 2026-10-15 are gone from the interface: the Méthode view now says "21 catégories : jusqu'à 400 apps" (C24), the README says "le premier email s'appuie sur un fait sourcé, chaque chiffre du corps est relié à un fait cité" (C3), and every fact shows "relevé le" next to its source link (C5). Claim C3 stays False as a claim about the product; what changed is that the interface no longer makes it.

What improved since 2026-10-15: the architecture rework put the rules in `core` use cases with tests (`DecideDraftTest`, `SendNextApprovedTest`, `PlanDraftsTest`, `ProcessRepliesTest`, `RunPeriodicJobsTest`), the routes are tested (`RoutesTest`: approval, 409, guard applied again, unsubscribe link and RFC 8058 POST), the agents have tests (`WriterAgentTest`, `ResearchAgentTest`, `RunTrackerTest`, `ReplyClassifierAgentTest`), and the purge and the opposition list are tested against PostgreSQL. Tests on disk: core 113, agents 30, data 113, app 48 (269 at HEAD, the rest uncommitted).

Third pass (2026-11-10, uncommitted, after the owner's decisions): the "no fit" verdict left the score, which is again the sum of fit, intent and warm path computed by code alone; the verdict filters the research queue and the contact book instead. The Play Store source is unbound. The number check of the guard compares whole numbers and single number words (C2). The Méthode copy and four README sentences were brought back inside what the code proves. Verdicts unchanged.

Re-check of the work in progress (second pass, uncommitted files): no verdict moved. The score now has two adjustments the interface does not describe (a cross-platform penalty of 20 fit points, a "no fit" adjustment of 60 that came from the researcher's conclusion; the third pass removed it, see below), the V10 migration cannot reach the opposition list or the contacts (read, not tested), and the Google Play source exists but nothing gives an account an Android package (C28, C24).

What did not improve: the guard still has no test for emojis, length, subject, links, "Re:" or unknown citations; the subject is still not scanned for numbers; follow-ups are still prefixed "Re:" (C6); no domain can be added to the opposition list (C18); agents, SMTP and IMAP have still never run end to end against a real LLM or a real mailbox. Rewritten prompts (research, synthesis) have never run against a real LLM: they prove no behaviour, only the code around them does.
