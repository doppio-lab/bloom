## Verdict

The architecture is sound and the safety design is real: claim-then-send in its own transaction, idempotency in
database constraints, `DRY_RUN` default, guard re-applied on human edits, hard stops before the LLM, dashboard
output escaped everywhere, no secret ever committed. The main risks are concentrated in three places:

1. The guard's "every number is sourced" promise has holes (substring match, LLM-written text treated as sourced,
   subject not checked).
2. Mail I/O has no timeouts and the SMTP retry path can send the same email twice.
3. Two of four modules are untested, and the untested ones are the ones that send email and talk to the LLM.

## P1: correctness and robustness

Guard and scoring (core)
- `MessageGuard.kt:54,158`: number separator class is `[  .,]` (two ASCII spaces), no NBSP / narrow NBSP. French page quotes use NBSP thousands separators, so a legitimate "100 000" is blocked or the check degrades to substring leniency. Add U+00A0 and U+202F.
- `MessageGuard.kt:62`: `stripCitations` removes every space before `.,;:!?` in the body that is actually sent, breaking French typography ("15 minutes ?" becomes "15 minutes?"). Only strip the space adjacent to a `[F:…]` marker.
- `MessageGuard.kt:142`: outbound-link allowlist is `"doppio-lab.com" in it`; `https://evil.io/?ref=doppio-lab.com` passes on follow-ups. Parse the host and compare exactly.
- `DiscoveryRules.kt:68,70,83-84`: exclusion entries "creme de la creme" and "groupe open" can never match because `tokens()` strips "de", "la", "groupe" from the account name but the list entries are compared raw. Tokenize `names` the same way `extra` is tokenized. Add a test.
- `DiscoveryRules.kt:73-75,86-87`: keyword exclusion is a raw substring on the lowercase name: "esn" excludes Fresnel, "talent" excludes Talentsoft, "conseil" excludes "Conseil départemental" buyers from DECP/BOAMP. Match on word boundaries over `tokens(name)`.
- `DiscoveryRules.kt:39-43`: `sameCompany` prefix test merges "Alan" with "Alan Allman Associates" and "Free" with "Freebox". Require the prefix to end on a token boundary.
- `Scoring.kt:129-133`: `intent` is capped at 50 but the reason lines are not; the dashboard can show "+45 +25 +22" against 50. Add a "plafonné à 50" line or scale.
- `SequenceEngine.kt:47-48`: comment says "un jour ouvré avant", code does `minusDays(1)`; a Monday holiday before a Tuesday slot puts the draft on the holiday.

Agents
- `WriterAgent.kt:86-92`, `ResearchAgent.kt:134-140`, `ReplyAndCoachAgents.kt:52-58`: `executeStructured(...).getOrThrow()` with no fixing parser: one malformed JSON (likely with Ollama) aborts the call with no retry; for the reply classifier the mail is retried every poll and burns tokens each time. Pass a `StructureFixingParser` on `llm.fast` or add one bounded retry.
- `Llm.kt:142-147,171-173`: budget is checked only before a run and failed runs log 0 tokens, so the retry storm above never counts toward `LLM_DAILY_TOKEN_BUDGET`. Record usage from the failed response or count through the event handler.
- `ReplyAndCoachAgents.kt:97-107`: `replyRateBySignal` is described to the coach as "par type de signal" but groups by `recommendedOffer`. Group by `repo.dominantSignal` or rename.
- `ResearchAgent.kt:144-155`: hypotheses citing "F:abc" or "[F:abc]" (the notation the writer prompt teaches) are dropped, and an `offer` written as "AUDIT" or "Discovery 2 jours" triggers `noFit`. Normalize ids and match the offer loosely.
- `ResearchAgent.kt:185`, `Prompts.kt:17-29`, `WriterAgent.kt:66`: page text and fact statements are injected inline with no delimiter and no "this is data, not instructions" sentence. The guard bounds the damage; still worth one delimited block and one sentence in both prompts.

Data and app
- `Database.kt:25-33`, `Orchestrator.kt:68-72`: the single-instance advisory lock is taken once on a raw `DriverManager` connection with no keepalive and never re-checked. A Postgres restart or dropped idle connection silently makes a second instance leader. Check `isValid()` on every loop tick and stop the loops when the lock is lost.
- `Sources.kt:58-62`, `Repository.kt:384-391`: fact ids are SHA-1 truncated to 8 hex chars (32 bits) used as a global primary key with `insertIgnore`; `JobBoardSource` embeds "publiée il y a N jours" in the statement so it creates a fresh fact per posting per night, which makes collisions a matter of months. Use the full hash and drop the age from the statement.
- `Orchestrator.kt:243-245`, `SequenceEngine.kt:56`: OUT_OF_OFFICE sets the enrollment to PAUSED and nothing resumes it; `followUpOn` is stored and never read. Resume on `followUpOn` or stop producing the state.
- `Repository.kt:531-536`, `Orchestrator.kt:149-152`: `nextToSend` ignores the step's due date; a follow-up drafted the day before can leave one send day early if approved inside that day's window. Store the earliest send instant on the draft and filter on it.
- `Mail.kt:170-185`, `Orchestrator.kt:213-240`: the IMAP pass has no cap and classifies every unread message (newsletters included) through the LLM; a message that throws in `textOf` is re-fetched and re-logged every 5 minutes forever. Cap per pass, filter on known contacts or References, record poison messages after N failures.
- `Mail.kt:105-106`, `Routes.kt:158`, `DiscoveryRoutes.kt:275`: emails are only checked for `@` and `InternetAddress.parse` splits on commas, so `a@x.fr, b@y.fr` sends to two people and escapes suppression. Validate with `InternetAddress(to, true)` on save and send; strip CR/LF from subjects.
- `Routes.kt:225-234`: unsubscribe executes on GET, so corporate link scanners (Safe Links, Proofpoint) opt prospects out. GET shows a confirmation page with a POST button; the RFC 8058 POST stays. Compare tokens with `MessageDigest.isEqual`, mask `/u/` in `CallLogging`.
- `Application.kt:185-190`, `Routes.kt:104,125,136`: malformed JSON, duplicate contact email and double enrollment all become 500 "erreur interne" with a stack trace; `POST /accounts` creates the account then fails on the contact with no transaction. Handle `BadRequestException` and unique violations (23505) as 400/409; wrap account + contacts in one `dbQuery`.
- `Application.kt:173-179`: no shutdown path (scope never cancelled, Hikari and the lock connection left to the JVM). Add an `ApplicationStopping` handler.
- `Orchestrator.kt:270-273,301-303`, `DiscoveryRoutes.kt:108-115`: a manual "Chercher maintenant" running when the nightly tick claims `discovery` makes the night's job record as done without running; the manual route is not gated on `leader`. Wait for the flag or re-claim later; gate the route.
- `Orchestrator.kt:149-158`: one email per 2-minute tick across all mailboxes, so 4 mailboxes cannot reach their 100/day quota (about 90 per window). Loop over mailboxes within a pass.
- `Repository.kt:369-374,610-619`: GDPR purge covers contacts and officers only; replies (full bodies), drafts, enrollments and events are kept forever and are orphaned when a contact is deleted. Cascade in the monthly `gdpr-purge` job and cap `Replies.body` retention.
- `Orchestrator.kt:234,247`: an UNSUBSCRIBE reply suppresses `mail.from`, not `contact.email`; a reply from an alias leaves the contact re-enrollable.
- `DiscoveryService.kt:353-354`, `Repository.kt:402-409`: signals are inserted every run with no dedup and no purge; scoring is still right (max per type) but `signals` and `discovery_seen` grow unbounded. Monthly purge.
- `Sources.kt:415`, `JobBoardSource.kt:28`, `Mail.kt:191`: no cap on fetched body size (`bodyAsText()` before truncation); a hostile or huge page can OOM the single instance. Check `Content-Type`, read at most ~2 MB through `bodyAsChannel()`.
- `ResearchAgent.kt:173,181`, `DiscoveryRules.kt:56-60`: the agent and `JobBoardSource` fetch whatever host sits in `account.domain`, which comes from scraped data (GitHub org website, App Store seller URL); no private-address filter and redirects are followed. Resolve the host before each fetch, refuse loopback / link-local / private ranges and `.internal` names, allow `https` only in `sameSite`.
- `Dropcontact.kt:45-52`: HTTP status never checked, so 401/402 (bad key, no credit) is logged as EMAIL_NOT_FOUND.
- `V2__discovery.sql:8`: the slug backfill differs from `CompanyNames.normalize` (no accent stripping, legal forms kept), so pre-V2 rows never match and duplicates hit the `accounts.domain UNIQUE` still in force from V1. Harmless on a fresh database; document or add a recompute migration.

## P2: security hardening

- `Application.kt:192-197`: basic auth with a non-constant-time compare and no rate limit; the password gives full control of outbound email. Install Ktor `RateLimit` on the `admin` block, compare with `MessageDigest.isEqual`.
- `Routes.kt:154-159,179-203`, `DiscoveryRoutes.kt:108-115,198-227`: state-changing POSTs need no JSON body (approve swallows a missing body with `getOrDefault(DecisionRequest())`) and no origin check; browsers attach Basic credentials to cross-site form POSTs, so a hostile page can approve a draft or blacklist an account. Reject `Sec-Fetch-Site: cross-site` on `/api`, stop defaulting on an unparseable body.
- `docker-compose.yml:24`: the app is published on all interfaces over plain HTTP with Basic credentials in every request; README has no TLS guidance. Bind `127.0.0.1:8080:8080`, document a reverse proxy, warn when `PUBLIC_BASE_URL` is not https and `DRY_RUN=false`.
- `DiscoveryRoutes.kt:235-242`: CSV export has no formula-injection guard for cells starting with `=`, `+`, `-`, `@`.
- `Mail.kt:98`, logback: dry-run logs recipient and full body at INFO; untrusted strings with newlines reach logs unescaped. Log the draft id, use `%replace(%msg){'[\r\n]', ' '}`.
- `.github/workflows/build.yml`: actions pinned by major tag, no `permissions: contents: read`. Pin to SHAs, add the permissions block.
- Dependencies: no known CVE at the listed versions for logback, postgres, jsoup, HikariCP, Exposed, Flyway, angus-mail, Kotlin; Ktor 3.3.3 and Koog 1.3.0 unverified. Dependabot would answer this continuously.

## P2: tests, build, CI

Tests (the biggest structural gap)
- `app` has zero tests although `ktor-server-test-host` is declared. Blocker: `AppContext` reads env and builds real clients in its initializer, and `Application.module()` reads `ADMIN_PASSWORD` itself. Make `AppContext` constructor-injected (repo, orchestrator, tokens, mail, scope), then `testApplication` tests for approve/reject conflict paths and the two unsubscribe routes first.
- `agents` has zero tests and the LLM cannot be faked: `Llm` builds the provider client in `init`. Add a constructor taking a `PromptExecutor` so a canned executor can be injected; this also gives a `FAKE` provider for offline UI work. Pure logic testable today: `hardStop` and quote trimming, `RunTracker.checkBudget`, `recordQuote` verbatim check and `sameSite` regex, `synthesize` id normalization, writer repair loop stopping at `maxRepairs`.
- Mail is testable without code change: `MailConfig` takes host/port, so GreenMail can receive the real MIME and assert `Message-ID`, `List-Unsubscribe`, `List-Unsubscribe-Post`, `In-Reply-To` / `References`, the "Re:" prefix and the footer. `UnsubscribeTokens` round trip is three five-line tests.
- Orchestrator collaborators are final classes; extract `Sender`, `Inbox`, `Drafter` interfaces so `sendApproved` (window, quota, spacing, claim, failure path) and `nightly` can run on `TestDatabase` with an injected clock.
- Sources and `DiscoveryService.ingest` can run on Ktor `MockEngine` fed by the fixtures already in `core/src/test/resources/fixtures/`.
- Repository: about 25 of ~90 public functions covered. Highest value untested: `mergeDiscovered` fill-only-empty, `excludeAccount` cascade, `purgeStaleContacts`, `isSuppressed` domain match, `decideDraft` with human edits.
- Core gaps that would have caught P0/P1 items above: guard numbers in subject, set vs substring, NBSP, URL host check, `stripCitations` on French punctuation; multi-word exclusion with stop words; keyword word boundaries; `SequenceEngine` holidays, `onReply`, `inWindow`; `Scoring` caps and tier boundaries.
- Schema drift: add one test asserting `SchemaUtils.statementsRequiredToActualizeScheme(all tables)` is empty after Flyway, since `Deals`, `Officers`, `AccountJobBoards`, `Events` are never queried by a test.
- Flaky patterns: `RepositoryTest.kt:67` compares a JVM `Instant.now().minusSeconds(5)` with the database's `now()` (clock skew after laptop sleep); `JobRunsTest.kt:31` holds the advisory lock on a connection that stays open for the JVM (order dependence for any future test).

Build and CI
- `Dockerfile:3-4`: `COPY . .` before the Gradle run, so touching README or `marketing/` re-downloads every dependency. Copy wrapper + build files first, resolve dependencies as a cached layer, `RUN --mount=type=cache,target=/root/.gradle`, extend `.dockerignore` with `marketing/`, `docs/`, `*.md`, `.github/`.
- No `gradle.properties`: add `org.gradle.parallel=true`, `org.gradle.caching=true`, `org.gradle.configuration-cache=true` (verify the Ktor plugin and Testcontainers under it), `org.gradle.jvmargs=-Xmx2g`.
- `build.gradle.kts:12`: `allWarningsAsErrors.set(false)` is the default (no-op). Turn it on with `extraWarnings.set(true)`; the build currently has zero warnings so this is free. Add ktlint or detekt wired into `check`.
- CI runs `build` (packaging) instead of `check`; add `gradle/actions/wrapper-validation`, a Dependabot config for `gradle`, `github-actions` and `docker`, and `permissions: contents: read`.
- Runtime image: no `HEALTHCHECK` although `/health` exists, no `JAVA_OPTS` (`-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError`), no `restart:` policy or healthcheck for `app` in compose.
- Dependency hygiene: `exposed-json` is unused (`data/build.gradle.kts:11`); `data` re-exports Exposed, ktor-client and coroutines as `api` and `agents` re-exports `core` and `data`, so `app` sees everything transitively. `Double.pct()` (`Sources.kt:426`), `Scoring.tier`, `Models.kt:234-235 iso()`, `Exclusions.isPossibleServiceCompany` are dead.
- `Repository.kt` (740 lines) should split along its existing section comments (Account, Discovery, Contact, Fact, Sequence, Send, Reply, Deal, Job, Event). Duplication to resolve while splitting: `blacklist()` runs the same query twice (199, 202); "stop a contact's sequences" exists three ways with different scopes (`Routes.kt:219` rewrites COMPLETED and REPLIED into STOPPED_UNSUBSCRIBE, corrupting history); enrollment is implemented twice (`DiscoveryRoutes.kt:55-69` vs `Routes.kt:128-140`) with different guards.
